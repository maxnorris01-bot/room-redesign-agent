# Session: stage D1.1, the first real-deployment bug and visible failures (2026-10-31)

Nothing here has run on the live deployment; the fix is untested there until it is redeployed. No git, gh, fly or docker command was run.

## What happened and why
On Fly every search failed within a second with a generic 500 and nothing in the log. `tracing.span` appended to the relative `runs/trace.jsonl`; the container runs as the non-root user `app`, `/app` was owned by root, so the job raised `PermissionError`. Tests ran as a user who could write there, and `deploy_smoke` had tracing disabled. The owner set `APP_TRACING_DISABLED=1` as a Fly secret as a stopgap.

## Changes
1. `tracing.span`: an `OSError` creating or writing the trace file is swallowed after one stderr line per process (file name and error class only). Errors in the traced body behave as before.
2. `Dockerfile`: `/app` is created and owned by `app` before the copy; `APP_TRACING_DISABLED=1` is set in the image and in `fly.toml [env]`. Local use keeps tracing.
3. `deploycheck`: checks the Dockerfile for `APP_TRACING_DISABLED=1` and a `chown app:app /app`, and `fly.toml` for the setting (with tests).
4. Failures are visible: a failed background job and an unexpected handler exception (deployment mode only) log ONE line, `shop error [tag] Class: redacted message at file:line`. The client still gets the generic sentence; 4xx `ApiError`s log nothing. The redaction also covers `cookie` and `shop_login` values (the test found `shop_login=ok` was not redacted before; `redact.py`'s pattern list gained those names).
5. `scripts/deploy_smoke.py` runs with a read-only working directory and tracing on, and fails if the search job does not finish or anything is written there.
6. Docs: ADR 0013 note, `docs/deploy.md`, todo, working notes.

## Would the smoke have caught it?
Yes. With the tracing guard temporarily reverted (the `except OSError` made inert, then put back), `make deploy-smoke` failed: the search job ended in state error and the new log line printed `PermissionError: ... 'runs' at src/app/tracing.py:68`. The guard is restored and the smoke passes. (As root the read-only directory would not block writes; the smoke prints whether it is read-only for the process.)
