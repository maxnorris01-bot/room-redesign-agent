Nothing here was run against a real Fly app, Neon database or Vercel project; no git, gh, fly or docker command was run. Everything was tested with mock providers, SQLite and local temporary files.

## What changed and why
- **P1 deployment mode** (`deploy.py`, `routes.py`, `server.py`): one route table for both modes; `/healthz`; origin secret (timing-safe, 403 empty); forwarded headers trusted only after it; Host/Origin checks; no CORS; error shape `{"error": {"code","message"}}`; `no-store` + `Vary: Cookie`. There is no thumbnail route, so the `private, max-age=3600` exception is moot.
- **P2 store** (`dbstore.py`, `store.py`): `SessionBackend`; JSON files (local) and SQL (SQLite/Postgres), migrations, retries.
- **P3 invites and login** (`auth.py`, `admin.py`): hashed codes and cookies, limiter, admin CLI, 404 isolation, a test that enumerates every table.
- **P4 caps** (`caps.py`, `thresholds.py`): guard before work, meter in the save transaction, `cap_reached` 429, kill switch 503, background jobs respect caps.
- **P5 outbound** (`thumbnails.py`): resolve once, pinned address with Host and SNI, blocked networks, same-host redirects only.
- **P6** `Dockerfile`, `.dockerignore`, `fly.toml`, `docs/deploy.md`, `make deploy-check`, `make deploy-smoke`.
- **P7** `docs/api-contract.md` with a route-table-vs-contract test, ADR 0013, SPEC, todo, working notes, browser check that the local page is unchanged.
