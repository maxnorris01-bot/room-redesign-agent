# 2026-11-04: clarifying questions in the search job (stage Q1)

## What changed and why

The backend of clarifying questions, behind `APP_SHOP_CLARIFY` (default off). Reasoning and the wait policy are in `docs/adr/0017-clarifying-questions-backend.md`; the API is in
`docs/api-contract.md`; the flag and the numbers are in `docs/deploy.md`. `evals/shop/thresholds.json` is untouched (SHA-256 `c64fe35a...d237`, checked).

- `src/app/shop/clarify_flow.py` (new): `ClarifyRun` (state, questions, pictures, answers, the wait policy), `Prefetch` / `PrefetchedSearch`, the question stage thread, `run_search_clarify`.
- `src/app/shop/search.py`: optional `rank_gate` on `run_query` (the apply point); the hard stop is moved by the time waited; an answers search when the search words change.
- `src/app/shop/jobs.py`, `progress.py`: the `clarify` object in the job status; `clarify_run` accessor. `routes.py`, `server.py`: `POST /job/{id}/answers`.
- `src/app/shop/service.py`: the clarify branch of the search job, `job_answers`, answer chips in the view, answer deletion through `/refine/remove`, category reset.
- `src/app/shop/store.py`: `Session.clarify` (omitted from the saved JSON while empty). `again.py`, `prep.py`: `base_query(session, config)` applies the stored answers.
- `src/app/config.py`: `shop_clarify`, `clarify_idle_grace_s`, `clarify_max_wait_s`, `clarify_candidates` with env names.
- `src/app/shop/clarify_mock.py`: the spike's canned callers moved here (the harness re-exports them), plus `priced`.
- Tests: `tests/test_shop_clarify_q1.py` (45). Three older tests were updated because this stage wires the spike in: the "nothing imports the spike" guard, the "only spike files changed" guard
  (now: `evals/shop` unchanged) and the contract's POST path set (templated paths excluded).

## Open questions / flags for review

- The live cost and latency of the question stage on the deployed machine are unmeasured; turn the flag on for a test and read `trace.clarify` in the search record.
- A visitor who never answers waits 6 s past ready-to-rank on every first search of a category; the shorter the better for the page, a number to tune after the front end exists.
- Answers apply to the first search and to later Shop Agains only; a different category clears them.
