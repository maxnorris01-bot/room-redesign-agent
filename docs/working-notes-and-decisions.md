# Working notes and decisions log - Room Redesign Agent

This is a different kind of record from `docs/sessions/*.md`. Session docs narrate what changed in
one sitting and are written for someone with zero context picking up the diff. This file is the
opposite shape: short, durable entries - a decision plus *why*, or an open item worth remembering -
meant to be skimmed months later when the reasoning behind something has otherwise been forgotten.
Append to it whenever a real decision gets made, not just at the end of a session. If something is
already fully documented elsewhere (a technical fix in a session doc, a known failure in the
README, a design tradeoff in an ADR), point to it here rather than duplicating it.

**2026-10-22 - Pick quality: sizes from titles and slugs, matching sets, seller variety, an image style check (ADR 0009 and 0010, proposed).** Fed by the latest live freeplay run. Sizes: fit was "unknown" on every pick although sizes sit in the data (`sanders-85-5-sofa`, `leif-54-media-unit`, `79"W` in titles); trust order is lookup features, then titles (store title first), then the URL slug; per-category plausible ranges discard mis-parses (and a real size on the wrong product); each candidate has `size_source` and `size_confidence` (slug = low, and the fit message says "approximate"); partial sizes get the longest-side rule only; a replacement more than 25% longer or shorter than the old piece gets a note. Sets: optional `matches_id` on perception furniture (additive, so `schema_version` stays 1), perception prompt v3 default, a note-text fallback marked inferred; a kept set member of a replaced item is a warning, `--replace-matching` replaces it, and the proposal gets the set as data. Families (storage, occasional tables, chairs, extra seating, lighting, bedroom storage) allow one slot each unless a replacement was explicitly requested, with the next category refilling; the item-count message says what happened; this lowers the per-room maximum (living 8, bedroom 9, office 7, dining 8), a deliberate trade against duplicates like media unit plus console table. Variety: freeplay rank pools cap any one seller at 3 and rank prompt v5 asks for variety; concentration is reported, not enforced across slots (that would need a barrier before lookups). Image check: thumbnail of each slot's top-ranked finalist fetched in parallel with its lookup (https only, public hosts, 3 s, 1 MB, image types only, no query in logs), style prompt v2 (default; v1 text-only stays) sees the room photo, thumbnails and the kept items' colours, a strong clash or poor match is a warning and can trigger the one revision. Mock mode serves a generated image; no test uses the network. Untuned guesses: size ranges, 25% replacement tolerance, seller cap 3, 10 thumbnails, 256 px, family groupings. Mock-verified only. See `docs/sessions/2026-10-22-pick-quality.md`.

**2026-10-22 - Freeplay mode ships first: no budget, a price tier, up to 10 pieces (ADR 0008, proposed).** The last live run showed the weak part: a flat per-item ceiling of 436.36 kept one cheap sofa when the median sofa in the search was 1519.20. So budget logic waits; freeplay (no `--budget`) is driven by style, quality and a price tier (value, mid, premium = thirds of the slot's own search prices, 3x-median outlier guard, bands under 3 results widen to the adjacent tier). `--items` 2 to 10 (5 default in freeplay, 3 in budget mode); accent lists now reach 10 categories per room type (office "desk lamp" became "task lamp" because the substring coverage rule made it unchoosable); a shortfall is a note, never padding. Lookup economy: 1 lookup per slot in freeplay with one fallback attempt, other finalists carried as unverified alternates (Google product link, "retailer link on request"), which deliberately relaxes ADR 0007's rule that alternates need a verified retailer URL; any alternate with no link is still dropped, and a pick must still be a retailer page. About 0.026 estimated provider dollars per slot (search + one lookup). Freeplay caps (steps, provider dollars) scale with the item count. Shipping: the live run counted three items "known" when two had null shipping and a total equal to the price; null means unknown (the provider had nothing), never free; each item now has `shipping_status` known, free or unknown. Prompts: rank v4, proposal v3 (older versions selectable; a version flag overrides both modes). `make spike` with no args is now a freeplay mock run. Untuned guesses: outlier factor 3, minimum band 3, cap scaling (6 spare steps, $0.06 provider per slot). Mock-verified only. See `docs/adr/0008-freeplay-mode.md`, `docs/sessions/2026-10-22-freeplay-mode.md`.

**2026-10-22 - Empty slots are explained, over-budget options are shown but never picked, and links must be real (ADR 0007 amended).** The first live run's sofa slot came back empty because all 25 results were over the per-item ceiling, and the output said only "25 over budget". Now search records price stats (min, median, max, counts); an empty slot prints the limit, the cheapest seen and up to two real over-limit options with verified retailer URLs (ranked from the 8 cheapest over-ceiling results, or the finalists the total cap dropped), written by code and kept out of the proposal, the totals and every check. Rank prompt v3 (v2 kept, `--rank-prompt-version`) says to pick the closest matches when everything is over the ceiling. Link hygiene: a finalist with no link of any kind is dropped (a Google-page-only finalist stays, as before); alternates must pass the same grounded rules as picks; empty lookups record why (http error status, no product_results, no stores). "media unit" is now a living-room accent after bookshelf, skipped when anything already covers it. The total line says how many items have known shipping instead of implying $0. Also fixed: the single-item budget result had lost its "shipping unknown" warning. The default mock run changed: its sofa slot is now over the limit (fixture prices scaled x8 for queries starting with "sofa"), so it no longer needs a revision. Judgement call: "must have a verified retailer product URL" is implemented as dropping `url_kind: none`; Google-panel fallbacks remain so a quota error does not empty every slot. Untuned guesses: 8 cheapest considered, 2 options per slot. Mock-verified only. See `docs/sessions/2026-10-22-over-budget-options-and-link-hygiene.md`.

**2026-10-21 - Keep-or-replace and a slot policy (ADR 0007, proposed); cleanup from the first live full run.** The first full live run proposed one item for a furnished room and gave that one slot the whole budget. Owner decisions: the visitor's choice arrives as `--replace` / `--keep` flags (ids or categories, synonyms honoured; unknown or conflicting names exit 2 with the valid list), defaulting from perception's `keepable`; with nothing named the slots are requested replacements, gaps, suggested replacements, then accents, up to 3. I added: a gap already covered by something that stays is skipped (the doubtful "side table beside sofa" beside a nesting side table), and accents beyond the cap are not reported as dropped. The equal budget split is replaced by a per-item ceiling (budget x 0.6 / 1.1, the same for every slot) plus a post-lookup total cap; sharing the money across slots is the proposal's job (prompt v2). Cleanup: the grounded check compares the search title with the store page's title and URL slug on size and material (the Judith/Leif example), flat goods skip the fit footprint rule, lookup failures print a WARNING (402/429 degrade to the Google page link; 401/403 are configuration errors and exit 4), and 429 now gets one immediate retry. Mock perception gained a desk so `--keep desk` works in mock. Untuned guesses still: item cap 0.6, shipping buffer 0.10, mismatch tolerance 1 inch. Mock-verified only. See `docs/adr/0007-keep-or-replace-and-slot-policy.md`, `docs/sessions/2026-10-21-keep-or-replace-and-cleanup.md`.

**2026-10-21 - Proposal and self-check built (ADR 0006, proposed): one call, four checks, one revision.** Owner scoping: the proposal is one structured model call; the model never supplies prices, sellers or URLs (code builds items from the real candidates and drops invented ids); the self-check is budget (total and per-item cap), fit (code, coarse, unknown when a product states no size), style (one text-only Haiku call) and grounded links and prices (code); a failure triggers one automatic revision, and whatever still fails is shown as a warning, never hidden. Decisions made while building: a revision that makes things worse is discarded in favour of the original; "unknown" never triggers a revision; a failed style call degrades to "unknown" rather than losing the proposal; the web-search mode's model-supplied prices fail the grounded check by design. The fit constants (0.6 side, 12% footprint, 0.5 confidence) and the 0.6 item cap are untuned guesses and will falsely fail large flat items such as rugs. Separate caps now: `APP_MAX_COST_USD` is Anthropic only, `APP_MAX_PROVIDER_COST_USD` (0.30) covers estimated provider dollars; ADR 0004's consequence line is updated. Mock-verified only. See `docs/adr/0006-proposal-and-self-check.md`, `docs/sessions/2026-10-21-proposal-and-self-check.md`.

**2026-10-21 - Retrieval default is now two-stage shopping data (ADR 0005, proposed).** Why: web-search retrieval had the model read pages and report prices and URLs itself (listing pages, one invented price). Now a shopping provider returns structured results, a small model only picks ids, and a per-product lookup supplies the retailer URL, price, shipping, total and dimensions; the model never supplies a price, seller or URL. Decisions inside it: Serper searches (cheap) and SerpApi looks up (shared product ids, direct retailer URLs); a lookup that fails or yields a non-product URL degrades to the Google panel URL or no URL, never an invented one (`url_kind`); provider calls are costed from two USD settings that are assumptions and count toward the cost cap; slots and lookups run concurrently, so the critical path is search + rank + slowest lookup. `web_search` mode stays selectable for comparison. Cost watch: six lookups per run at the assumed $0.025 is about $0.15, which dwarfs the old search cost; check the real prices before reading anything into the mock table. Details: `docs/adr/0005-two-stage-shopping-retrieval.md`, `docs/sessions/2026-10-21-two-stage-shopping-retrieval.md`.

**2026-10-21 - Default-slot coverage counts decor and fixed items, with synonyms.** The last live room already had a rug and a floor lamp (as decor), yet the default slots would have proposed both. "Already covered" now also checks `art_and_decor` kinds and `fixed_items` categories, and folds synonyms (area rug = rug; floor lamp = lamp = torchiere). Side effect to remember: any lamp covers a "floor lamp" slot, by design.

**2026-10-21 - "coolpale" in style_descriptors came from the model, not our code.** Evidence: the string appears only in `result.json` of run 20261021T032130Z-4a360a (the parsed output); the trace holds no raw text. Between the model's JSON and `result.json` the data goes `json.loads` -> pydantic -> `model_dump` -> `json.dumps`, and no string operation in `src/` touches those fields (the only joins are downstream in the retrieval prompt or on our own strings). The v1 prompt contains neither "cool" nor "pale", so templating is not a source; image prep changes pixels, and schema stripping changes only the request schema. A test pins the passthrough. Not provable from that run's artifacts because the raw text was not saved; `result.json` now stores `perception_raw_text`. Mitigation: perception prompt v2 requires separate lowercase phrases and says never to run words together.

**2026-10-21 - What changed in the latency and retrieval hygiene session.** Retrieval slots now run concurrently (one thread per slot) behind a lock-protected `Budget`: the step cap stays exact, but the cost cap can overshoot by the calls already in flight, since they cannot be cancelled and still bill. A candidate must now be a product-page URL as well as present in the search results; listing, collection, category and search URLs are dropped with a reason. Perception prompt v2 asks for shorter output (notes of 12 words or fewer, at most 6 decor entries, at most 4 uncertainties, 3 to 5 separate lowercase style phrases, gaps only when clearly absent and not already covered); no `maxItems` was added, and the run records output sizes so we can see whether v2 is obeyed. CLI flags make perception experiments one-liners. Streaming perception now records time to first token. See `docs/sessions/2026-10-21-latency-and-retrieval-hygiene.md`.

**2026-10-21 - Latency limit: first 20 s, then "judge the wait by feel".** The owner first set a 20 s limit, then relaxed it: no hard limit for now; the owner judges the wait by feel on real runs. So this session reduced wall-clock time where cheap and safe and made timing measurable per stage, rather than chasing a number. ADR 0004 targets still wait until the owner has felt a real run.

**2026-10-18 - Spike skeleton decisions (Claude Code session 1).** Details in `docs/sessions/2026-10-18-spike-skeleton.md`; the reasoning worth keeping:

- *Images:* every photo goes through `app.images.prepare_image`: orientation applied, then the image is rebuilt from raw pixels (so EXIF/GPS/XMP/ICC cannot ride along), downscaled to a 1568 px long edge (configurable, `APP_IMAGE_MAX_EDGE`; image tokens scale with area, so this is also the cost lever), re-encoded as JPEG q85. Never upscaled. Tests and the mock spike use a generated image carrying fake GPS, so no real photo is needed anywhere.
- *Pricing:* one table, `src/app/pricing.py`, with source URL and date (checked 2026-10-18). Costs are always *estimates* from API-reported usage plus a configurable per-search estimate (`$0.01`, from "$10 per 1,000 searches"). Haiku 5.5's prompt-length tier is modeled; an unpriced model is costed at the highest known rate so the cap errs conservative and the table prints a warning.
- *Models:* defaults `claude-sonnet-5-5` (perception) and `claude-haiku-5-5` (retrieval), both confirmed on the models overview page. Config only; recorded per stage in trace and table.
- *Web search tool version:* default is the basic `web_search_20250305` (works on every model, results go straight into context) rather than the `_20260209`+ dynamic-filtering variants, because those run code execution under the hood and I could not verify Haiku 5.5 support or the token trade-off without a live call. `APP_WEB_SEARCH_TOOL` switches it so the two can be compared live.
- *Thinking effort:* `APP_EFFORT_PERCEPTION=medium`, `APP_EFFORT_RETRIEVAL=low` are guesses (thinking tokens bill as output). Explore live; they may be the biggest cost lever.
- *Perception schema (`schema_version` 1):* top-down plan in normalized coordinates (north = wall farthest from camera). Added a `furniture_gaps` list (categories the room visibly lacks) so retrieval slots have something to derive from. Living things are a separate list, never in `furniture`. Bounds (0..1 positions, confidence, positive sizes) are validated by pydantic *after* parsing; the JSON Schema sent to the API strips `maxItems`/`maxLength`/numeric bounds rather than pretending they work.
- *Slot derivation:* done in code, not by an LLM call, so the number of searching calls is bounded and inspectable. Order: furniture marked replaceable (`keepable: unlikely`), then gaps, then room-type defaults only if neither exists. Keepable items are never slots. Total budget is split equally across slots (spike heuristic). Slots run sequentially under one shared `Budget` (steps and dollars cap the whole run); parallelizing is a latency lever to test later (todo). [Superseded: slots run concurrently; slot order and the budget ceiling are now ADR 0007.]
- *URL guard:* a candidate is kept only if its URL appeared in that call's search results (ignoring only a `#fragment` and trailing slash). The mock deliberately returns one unverified URL per slot so the guard visibly fires in every mock run.

**2026-10-18 - Cost and latency targets: explore one room, then lock.** Proposed targets (perception plus retrieval for one room at or under $0.08 and 30 s; full run at or under $0.20 mean and p95 at or under 60 s with streamed progress) are not locked.
